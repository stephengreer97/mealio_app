One place the comment and the code disagree

StoreScripts.workerCount in webview-scripts/index.ts is documented as “Defaults to 5. Lower it for stores with aggressive anti-bot (ALDI: 3).” The call site is scripts?.workerCount ?? 3, and the note beside it records the change (“3 workers (was 5)”). The effective default is 3, and it has been for as long as that call site has read ?? 3 — so the interface docblock now describes a value no store gets. It is stale documentation rather than a behavioural bug: every store either sets workerCount explicitly or wants the low default. Worth a one-line fix next time someone is in that file.

What is deliberately not remote

Everything in tables 2–4 is remotely tunable. Nothing in table 1 is. KROGER_BRAND_IDS and WEBVIEW_STORE_IDS assert that this binary contains code for a store, and no server response can make that true — a database row would otherwise promise automation the installed app cannot deliver. The catalog can add a store's name; only a release can add its automation.
